## 二、專案定位

把資產鑄成 Token 只需要一個 ERC-20。真正困難的是回答:**這顆 Token 值多少錢?**

黃金、基金份額這類資產沒有 24/7 深度市場,現行做法都有結構性缺陷:

| 現行做法 | 失效原因 |
| --- | --- |
| 單一預言機餵價 | 單點故障;來源被操縱即全盤錯誤 |
| 單一 CEX 參考價 | 休市、下架、流動性枯竭時斷線 |
| 人工審核上架 | 中心化審批,數週流程,無法規模化 |

DEXless 的作法是**不預設任何來源可信**:要求多個獨立來源在鏈上互相驗證,
通過五道檢查後取中位數,並把每一筆拒絕的理由寫成鏈上事件。
市場也不由委員會核准——它必須讓自己的價格來源撐過「養熟期」,通過後由任何地址啟用。

## 六、要求 5:RWA 能力

### 5(2) — Infra 四項核心能力

#### ① 數據上鏈模組(API / Oracle → on-chain)

每筆報價進入 `PriceValidationEngine` 後,須通過五道鏈上檢查:

| 檢查 | 規則 | 主網設定 |
| --- | --- | --- |
| 新鮮度 | 報價年齡 ≤ maxStaleness | 900 秒 |
| 價差控制 | (ask − bid) / mid ≤ maxSpreadBps | 50 bps |
| 深度驗證 | 可成交名目 ≥ minDepth | 見下註 |
| 偏離度 | \|price − median\| / median ≤ maxDeviationBps | 200 bps |
| 跨源一致性 | 存活來源 ≥ minSources,且橫跨 ≥ minDistinctKinds 類別 | 3 / 2 |

最終價格取存活來源的**中位數**而非平均數——對單一離群值免疫。
連續失敗達 3 次,Feed 自動暫停供價。每一筆拒絕皆以 `SourceRejected` 事件寫上鏈。

**關於深度門檻:** 本 feed 的 `minDepth` 設為 0。訂單簿型來源照實回報聚合深度
(實測 10 萬至 20 萬美元),但預言機提供的是參考價、並無訂單簿,誠實回報為 0。
若以深度設限,將排除預言機並使 feed 失去跨類別多樣性。所有深度數值皆公開於鏈上供檢視,
守關責任交由新鮮度、價差、偏離度與跨類別一致性承擔。

#### ② 資產驗證 / 審計機制

`RWAAssetRegistry` 要求託管方定期上鏈申報儲備量。申報逾 35 天未更新,資產自動失去可鑄造資格。
法律文件存於 IPFS,鏈上僅留 CID 與 keccak256 摘要,任何人可驗證手上文件與登記版本一致。

#### ③ 合規 / KYC / 身份模組

`ComplianceRegistry` 由持牌機構於鏈下執行 KYC,鏈上僅寫入**記錄雜湊**,個資永不上鏈。
支援投資人分級、效期、撤銷與司法管轄區封鎖;RWAToken 的每一次轉帳都會查詢此登記。

#### ④ 資產發行工具(合約模板)

`MarketFactory` 提供無需許可的市場創建:任何人可提案,無人審批。
市場必須讓其價格來源撐過 **1 小時養熟期 + 12 輪乾淨驗證**,
通過後由**任何地址**啟用——是合約在判定,不是委員會。
保證金 0.005 BNB,無論啟用或駁回皆全額退還。

#### 系統架構

```
鏈下資料層                    BNB Chain 主網                     執行層
──────────                   ──────────────                    ──────
Binance  ─┐
OKX      ─┼─ submitQuote ─→  PriceValidationEngine  ─┐
Gate.io  ─┤                  新鮮度 · 價差 · 深度      │
Chainlink─┤                  偏離度 · 跨源一致性       ├→ MarketFactory ─→ Orderly
Pyth     ─┘                                          │   無需許可市場創建   共享流動性
                                                     │
託管方 ──── attestCustody ─→  RWAAssetRegistry ──────┤
                                    │                │
KYC 機構 ─── attest ────────→  ComplianceRegistry    │
                                    │                │
                                    └──→ RWAToken ───┘
                                         1:1 擔保
                                            │

```

所有合約皆為**無需許可讀取**:任何第三方協議都能直接呼叫 `getPrice()` 取得經驗證的 RWA 價格,
或呼叫 `isMintable()` 檢查資產擔保狀態。DEXless 是 BNB Chain 上任何 RWA 專案都能接入的
公共定價基礎設施。

### 5(1) — 資產上鏈:1:1 擔保由合約強制

除 Infra 能力外,另完成一個資產的上鏈與 mint。
**1:1 足額擔保並非政策承諾,而是合約層的不變量:**

```solidity
uint256 attested  = assetRegistry.attestedUnits(assetId);
uint256 newSupply = totalSupply() + amount;
if (newSupply > attested) revert ExceedsAttestedReserves(newSupply, attested);
```

鑄造量永遠不可能超過託管方最新申報的儲備量——超額鑄造在合約層直接 revert。
託管申報過期則鑄造全面停止。任何人可呼叫 `backingRatioBps()` 查詢即時擔保率
(目前為 2500%)。贖回即銷毀,鏈上供給與鏈下儲備由設計本身收斂。

> **待補:** 資產類型與來源、Token 所代表的權利、發行主體與託管機構等法律欄位,
> 須經律師與託管方確認後填寫。本次發行採 whitelist-only、不公開募集,
> 並於 `ComplianceRegistry` 以合約強制執行。
>
> 我們不會在此填入無法佐證的內容。該份 1–2 頁資產說明文件將於法律確認完成後提交。

我們認為主動揭露優於事後被發現。以下為目前尚未完成或存在限制之處:

  (`DEFAULT_ADMIN_ROLE` 與操作角色可分離),部署腳本亦支援多簽交接,尚未執行。

  非法定 KYC 查核結果。

  目前價格來源為 CEX 訂單簿與預言機。
- **封閉 Beta 尚未開始。** 真實第三方用戶的地址清單將於送件時提供。
